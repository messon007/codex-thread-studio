# Agent Teams：审查后隔离验证计划

状态：GPT-6.2-Astra 第二轮已批准 G1/G2 隔离探针；部分探针已运行，见 [验证结果](verification-results.md)。G3/G4 与产品开发未批准。

## 放行原则

设计审查、隔离能力验证、产品开发是三个独立阶段。审查者必须明确批准具体验证范围，才运行该范围；测试通过才允许依赖该能力的开发。
任何验证都不得操作用户现有会话、改写用户 Codex 配置、取消其队列消息、启动其任务或扩大其权限。
不把“模型返回了完成文字”“配置项存在”“CLI 退出 0”当作行为保证。

开发分支固定为 `feat/agent-teams`，不合入 main。工作目录、构建产物和测试运行数据放在 `/media/rui/` 下本任务的专用目录；不复用其他会话正在写入的 target，不在 `/tmp` 内存盘构建。

## G1：工具调用身份

候选采用受认证 MCP 连接加独立 App Server 事件关联；Hooks＋普通 CLI 不作为默认成员写入通道。
探针只有无业务副作用的 inspect/echo 操作，使用虚构组、成员和请求，不包含委派或文件修改。

输入：一个独立测试 App Server、两条在安装工具之前已存在且有可核对上下文标记的测试 thread、一个仅记录接入证据的本地测试 MCP 服务。工具安装前后分别记录 thread ID、cwd、模型、权限与历史标记；不新建替代 thread。
必须区分：模型原生调用、宿主 `mcpServer/tool/call` 直调、直接 HTTP 调用、重放、伪造 metadata、错线程/错后端。

检查：

1. 模型工具调用能否在独立的可信 App Server 通道观察到先于请求执行的事件，精确关联 backend generation、thread、turn、call/item、server、tool 和规范化参数。
2. 客户端直调能否生成同样的事件。如果无法区分，不将该事件当作成员身份凭证。
3. 同一模型调用事件只可消费一次；传输重试以已记录的请求摘要返回原结果，不授权新意图。
4. MCP metadata 缺失/冲突、错误 tool/server、跨 thread、参数替换、旧 generation 的请求均拒绝。
5. 服务重启、连接重连、事件顺序倒置和超时只能得到可解释的拒绝/待核对，不猜测授权。
6. 两个 thread 同时发起相同工具/参数的调用，以及宿主 direct-call 与合法模型请求重叠；不得把一方的授权或读结果返回给另一方。
7. 已有会话在安全轮次边界重载工具；分别保存工具列表、宿主直调、真实模型调用的证据，确认原 cwd/模型/权限/历史不变。

通过条件：全部负例拒绝，真实模型调用可完成，并得到可复现的事件来源说明。否则身份能力未通过，不开放成员写操作。
普通 Studio 用户 gateway bearer 不交给 Agent/CLI，也不把它当作成员级凭证。

## G2：原生队列语义

只允许在测试 thread 中使用带唯一 delivery ID 的无副作用文本消息。
两个测试客户端竞争同一原生队列，模拟 Studio 与 CLI；记录原生事件、关联 ID 和开始顺序。

检查：

1. 活跃 Turn 中 add/start 是排队、拒绝还是注入；任何注入当前工作都视为不满足 Teams 要求。
2. 队列是否自动消费，谁有消费权，能否在服务未授权时由其他客户端启动 Teams 项。
3. 队首顺序与多客户端 start 竞争，是否有原子拒绝、幂等标识和可查询回执。
4. start 与 delete/pause/cancel 并发时的线性化结果；不得把 already started 报成 withdrawn。
5. 队列接受后的断线/重启，是否能按稳定 ID 判定未提交、已接收或不确定。
6. 人工暂停、审批等待、监督保留和真实活跃状态是否存在可靠的后台门控来源；页面缓存不算。
7. 每次拒绝/撤回记录是否额外创建 Turn、改变原 Turn 或吞掉相邻人工队列项；仅“模型没有收到标记”不足以判通过。

通过条件：能写出一个无竞态、不可被普通外部客户端绕过的消费授权实现；否则禁止把 Teams 工作放入会被自动/外部消费的原生队列。
不得用“read idle 然后 turn/start”、轮询频率或单个页面锁替代这个条件。
测试只能覆盖有限竞态样本；线性化保证必须另有固定版本实现/协议证据。报告分别列“观察到的样本行为”和“已证明/仍未知的保证”，不把零次复现当作竞态不存在。

## G3：Hook 只作为辅助的反证验证

不是默认必做；仅在 G2 结果说明有具体必要时，由审查者另行批准。
UserPromptSubmit 的官方输入已经带 active turn_id，因此不能预先认定它发生在 Turn 创建之前。

在隔离配置中检查 queue/start、自动消费、外部客户端发起、恢复、Hook 未加载/未信任/超时/崩溃各路径。
如果有路径可以跳过 Hook，或 Hook 失败继续执行，它不能作为取消/关闭的最终门控。
即使拦截 prompt 成功，也不证明没有打断已有 Turn、抢占队首、越过监督保留或建立可靠成员身份。

## G4：通用队列基础的范围决策

本项是范围设计决策，不是探针或产品代码的开发授权。现有队列的服务端能力不足时，必须先定义独立的通用 QueuePort 改进：持久队列、唯一后台消费权、人工/监督保留、稳定 ID 与暂停/取消的线性化。
该改进不得依赖 Teams 业务模型，Teams 关闭后它仍能作为普通队列运行。
若跨客户端的独占消费/保留无法落实，需要停在 capability unavailable，记录上游缺口并修改方案复审；不降级或未经说明缩小非抢占承诺。
