## 使用边界

- 同一 OS 用户、受信宿主和可修改本地 Codex 配置的进程具有管理能力。MCP 元数据和匹配的原生 item 用于合作式角色归属与防误路由；这套机制不提供不同安全租户间的隔离。用户主动安装的后端级注册可在使用同一配置的其他会话中显示工具名。
- 可确认未发送或已被原生明确删除的通知才可重新进入发送流程。断线发生在 send intent 之后时，服务保留不确定结果。分页查找原生历史有上限，未找到不证明未执行。显式 abandon 只释放普通消息队列的阻塞，严格保留、恢复组派发和归档仍须处理可能存在的在途工作。
- Studio 内相同消息的多页消费得到持久仲裁。绕过 Studio 的外部客户端受原生队列顺序约束；自定义跨回合监督需要登记保留。跨客户端按墙钟提交时间的全局 FIFO、跨 Studio 实例总线和远端/WSL 工具桥接没有通过本次验证。
- 已授权交接的原生项可能在暂停与撤回请求竞争时开始。产品返回待核对状态，保留已启动的原回合，后续不确定结果不能触发自动重发。域内命令有稳定写入回执；跨文件配置、队列和领域库存储的收尾需要从持久事实恢复。
- 真实付费模型是否会从任意自然语言目标自主选择正确的工具、如何拆任务、是否达成业务目标，仍取决于模型和项目。上述闭环证据验证协议与状态转移，不外推不同 Codex 版本的工具装载、队列行为或远程部署兼容性。
